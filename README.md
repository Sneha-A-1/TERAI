# TERAI: Value-of-Information-Driven Multi-Agent Data Retrieval and Two-Timescale Resource Allocation for Smart Agriculture over 6G Terrestrial–Satellite Edge Networks

This repository contains the complete, executable research pipeline behind the manuscript in
`manuscript/`. Every table, figure and number in the manuscript is generated by the code in this repository from the
data in `data/raw`.

## Research problem
Agricultural decision support in mountainous regions depends on heterogeneous observations
(gauge-based rainfall, reanalysis weather, Sentinel-1 radar backscatter, SMAP passive-microwave
soil moisture) that must reach a regional estimator over scarce and weather-sensitive links:
terrestrial backhaul in the plains and a shared low-Earth-orbit (LEO) satellite beam in the
hills. Which observations should each edge site deliver, and when, so that soil-moisture
estimates (and the irrigation decisions derived from them) stay accurate while satellite
slots and energy are spent sparingly? And how should the resulting irrigation-command bursts
be scheduled in a 6G RAN slice?

## Link with the PhD objectives
* Objective 1 (review): Section II and Table I of the manuscript.
* Objective 2 (data retrieval for urgent/strategic insights): value-of-information-driven retrieval (SCAF + CoVIR).
* Objective 3 (optimised resource scheduling): constrained multi-agent scheduling (CoVIR) and RB scheduling (DRIP).
* Objective 4 (multi-layer framework): field / RAN / edge / backhaul / cloud architecture (TERAI).

## Methodology (names used in the paper)
| Component | File | Description |
|---|---|---|
| TERAI | whole repository | Two-timescale Edge Resource Allocation for agricultural Intelligence |
| SCAF | `src/terai/forecast.py` | Staleness-Conditioned Attention Fusion estimator of regional soil moisture (residual over SMAP persistence, per-dimension staleness gate, staleness augmentation, early stopping) |
| VoI | `experiments/e2_voi.py`, `src/terai/env.py` | measured value of freshness and edge-computable innovation features |
| CoVIR | `src/terai/marl.py` | Cooperative Value-of-Information Retrieval: CTDE, shared actor, centralised critic, PPO, primal-dual Lagrange multipliers, behaviour-cloning initialisation from the decentralised VoI threshold rule, critic warm-up, checkpoint selection on the training simulator |
| DRIP | `src/terai/ran.py` | Deadline-aware drift-plus-penalty RB scheduler with virtual deadline-violation queues |
| Baselines | `src/terai/policies.py`, `src/terai/marl.py` | Random, Round-robin, Max-age (Greedy), Whittle's index (Kadota et al., IEEE/ACM ToN 2018, Eq. 57), VoI-greedy, decentralised VoI threshold, exhaustive myopic optimum, IPPO, centralised PPO, QMIX (Rashid et al., ICML 2018); RAN: RR, PF, EDF, Max-Weight |

## Data
See `data/README.md`. Real data: SMAP SPL3SMP_E v006 statistics, IMD gridded rainfall and
temperature, NASA POWER, Sentinel-1 VV/VH, ERA5-Land (validation), Mendeley IoT log,
545 Farm-Flow flow records, Landsat 8/9 metadata. **All forecasting, value-of-information and
retrieval results use the real data with a strict temporal split** (train: 15 Oct 2022 - 31 Dec
2023; test: 1 Jan - 31 Oct 2024). **Synthetic data** (generated after examining the original
datasets, `src/terai/synth.py`) drive the network workloads only: Farm-Flow-calibrated flows
(Gaussian copula), telemetry timing resampled from the Mendeley log, and scaled deployments.

## Installation
```bash
conda env create -f environment.yml && conda activate terai-6g
# or: python -m pip install -r requirements.txt   (Python 3.13)
```
CPU only; no GPU is needed.

## Reproduction
```bash
bash scripts/run_all.sh          # about 3-4 h on a 2-core CPU
```
or step by step:
```bash
python experiments/e5_data_synth.py          # data facts + synthetic-data fidelity
python experiments/e1_forecast.py            # SCAF vs baselines (10 seeds) + estimator ensemble
python experiments/e0_crossfit_estimators.py # cross-fitted estimators (simulator ablation)
python experiments/e2_voi.py                 # measured value of freshness
python experiments/e3_slow.py                # main multi-agent comparison (10 seeds) + ablations
#   (optional) E3_REUSE_HEUR=data/processed/e3_slow_v1_heuristics.json reuses the heuristic
#   evaluations of an earlier run of the same script (identical code and seeds); this was
#   done for the reported results
python experiments/e4_policy_analysis.py     # generalisation (train-period replay), slot-budget sensitivity, timing
python experiments/e6_ran.py                 # RAN slice: schedulers, scaling, flood, FR1 vs FR3
python scripts/make_outputs.py               # all tables, figures and manuscript macros
cd manuscript && pdflatex main && bibtex main && pdflatex main && pdflatex main
python tests/test_core.py                    # unit tests
```

## Outputs
* `results/raw/*.json` – raw results of every experiment (per seed).
* `results/tables/*.csv`, `manuscript/tables/*.tex` – tables (single numbers; means and standard deviations in separate columns).
* `results/figures/*.pdf`, `manuscript/figures/*.pdf` – figures.
* `manuscript/results_macros.tex`, `results/macros.json` – every number quoted in the text.
* `manuscript/main.pdf` – compiled manuscript.

## Reproducibility details
Seeds 0-9 for learning methods (5 for ablations); environment seeds 1000+seed for the test
season (2000+seed in E4); model selection of every learned method uses only a fixed validation
copy of the training simulator (seed 9000), never 2024 data; all parameters are in `src/terai/config.py`, `src/terai/env.py` (SlowConfig),
`src/terai/marl.py` (PPOConfig, QMIXConfig) and `src/terai/ran.py` (RanConfig), and are printed
in the manuscript's parameter table by `scripts/make_outputs.py`. Hardware used: 2-core x86 CPU,
7 GB RAM. Library versions: see `requirements.txt`.

## Limitations
Regional (not district-level) SMAP target; district IMD/POWER series act as stand-ins for
district station reports; LEO backhaul, rain-to-attenuation conversion, terminal energy and RAN
slice are simulations with documented parameters (no physical 6G deployment); synthetic
workloads are calibrated on 545 Farm-Flow records; one test season. See Section IX of the
manuscript.
